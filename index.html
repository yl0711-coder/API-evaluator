高级 · 压测压力测试

以持续并发向目标模型/上游中转施加恒定负载，测吞吐(QPS)、延迟分位(p50–p99)、成功率与错误构成。用于判断上游能否支撑规模化团队使用。

开始前请注意

压测会发出大量真实请求、产生真实计费；建议先用廉价模型验证链路，再压目标模型。请在本机等有余量的机器上跑，不要在对外服务的生产机上压测。压测与其它测试共用同一进程，其高并发会拉高同时在跑任务的延迟（反之亦然）：请在压测期间不要并行发起其它测试，以免两边结果互相污染、都不可信。

协议是怎么定的？测试报 404 怎么办

协议按模型名推断：分组内 claude 占多数则用 Claude Messages，否则 OpenAI Compatible。由于这些渠道走 new-api 的 /v1 中继（对外通常是 OpenAI 兼容协议），若测试报 404 请把渠道协议改为 OpenAI Compatible。

批量导入

从 sub2api 上游渠道导入测试分组

读取你名下名称含「测试」的 API 密钥（仅启用状态），每个密钥建一个渠道（Key 自动填入），再按密钥所属分组把该分组下的模型建成测试模型。

协议是怎么定的？导入失败怎么办

协议按上游分组声明的 platform 判定（anthropic 用 Claude Messages，其余用 OpenAI Compatible），不靠猜模型名。若该站点未启用「模型广场」，则改为按每个密钥读取其实际可调模型，此时协议一律按 OpenAI Compatible 处理。这些渠道走 sub2api 的 /v1 中继，若测试报 404 请把渠道协议改为 OpenAI Compatible。

若持续报登录失败或 401：sub2api 会把登录凭证绑定到发起请求的 IP 与客户端标识，本工具已在服务端完成登录以规避该限制；仍失败请确认邮箱密码，或该账号是否开启了两步验证。
