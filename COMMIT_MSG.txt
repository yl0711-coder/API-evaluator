perf: 静态资源压缩 + API 响应压缩 + HTTP 连接池

## 改动摘要

针对"线上慢、本地快"问题，添加 HTTP 响应压缩、缓存头优化，以及上游请求的连接池。

### 核心改进

1. **静态资源压缩**（首屏从 426 KB → 98 KB，节省 77%）
   - 支持 brotli / gzip 内容协商
   - 压缩结果内存缓存（LRU，最多 200 条）
   - 带 hash 的资源强缓存 1 年（immutable）
   - index.html 用 etag + no-cache

2. **API 响应压缩**（报告对比从 988 KB → 29 KB，节省 97%）
   - 超过 1 KB 才压缩（避免小响应开销）
   - 已优化 3 个大响应端点：
     - POST /api/reports/compare
     - POST /api/reports/compare/multi
     - GET /api/support-bundle

3. **HTTP 连接池**（上游请求握手开销从累计数秒降至一次性 100-300ms）
   - 使用 undici 的 setGlobalDispatcher 启用全局连接池
   - 每个 origin 最多 256 个并发连接
   - 空闲连接保持 60 秒，最长存活 10 分钟
   - 适用于所有上游 API 请求（fetch 调用）
   - 高频测试场景（准入/稳定性/压测）向同一端点发送几十到上百个请求时，
     TCP + TLS 握手从每次都要做（每次 100-300ms）降为每个 origin 只需一次

### 新增文件

- server/compression.mjs — 压缩与缓存工具
- server/http-pool.mjs — HTTP 连接池配置
- tests/compression.test.mjs — 单元测试
- scripts/verify-compression.mjs — 压缩功能验证脚本
- scripts/verify-http-pool.mjs — 连接池验证脚本
- docs/compression-optimization.md — 详细文档

### 修改文件

- server.mjs — 引入 http-pool（在所有 import 之前）和 compression，
  serveStatic 和 3 个端点改用压缩版本

### 验证方法

```bash
pnpm test tests/compression.test.mjs
node scripts/verify-compression.mjs  # 需先启动服务器
node scripts/verify-http-pool.mjs    # 验证连接池效果
```

浏览器 DevTools Network 面板应显示：
- Response Headers 有 content-encoding: br 或 gzip
- Size 列显示传输大小远小于资源大小
- /assets/*.js 有 cache-control: immutable

### 技术细节

- Brotli 优先于 gzip（更高压缩率）
- 降级策略：不支持的客户端回退到未压缩
- 缓存 key = `${encoding}:${etag}`，避免重复压缩
- JSON 保留 pretty-print（调试友好），压缩收益来自 gzip 而非移除缩进
- 连接池禁用 HTTP 流水线（pipelining: 0），避免与某些中转不兼容
