# 报警规则是怎么触发的？

规则分三种类型，在表单的「规则类型」里选：

- **阈值规则**：一句判断——**某个目标 × 某项指标 × 比较符 × 阈值**。本文档大部分内容讲的是它。
- **稳定性抖动**：复合规则，看**单次运行内部**的离散度（这一次里快慢差多少）。见文末专门一节。
- **稳定性退化**：复合规则，看**与自身历史比**（最近几次比先前一段时间差了多少）。见文末专门一节。

后两种是互补的，抓的不是同一类问题：抖动看**一次运行内部**的参差，退化看**跨运行的水平下移**。实测举例——某次运行 P95 冲到 115 秒（抖动 11.74×，抖动规则命中），但它前后几次都正常，最近三次的中位数没被这一次拉动，所以退化规则不响；反过来，连着两三次都从 33 秒慢到 50 秒，每一次内部都不算特别参差（抖动规则不响），退化规则会响。

测试跑完（手动跑或自动定时任务跑完都算），系统会把这次结果里能取到的指标，过一遍所有已启用的规则，命中就发邮件，不命中就什么都不做，不会记录、不会提示。

## 适用范围

- **全部渠道 + 模型**：不管这次测的是哪个渠道哪个模型，只要指标命中就算。
- **指定渠道 + 模型**：只对你选定的那一个目标生效，其它目标测试再差也不会触发这条规则。

## 触发指标：来自哪种测试、取值是什么

不是每种测试类型都会产出全部 8 个指标——选中的指标只在对应测试类型跑完后才可能被评估，其它测试类型跑完会直接跳过这条规则（不算命中，也不算异常）。

| 指标 | 产出于哪些测试 | 取值 | 说明 |
|---|---|---|---|
| **成功率** | 准入、稳定性、批量准入、批量稳定性、快速验证 | 0～1 的小数 | 请求成功的比例 |
| **P95 耗时（毫秒）** | 准入、稳定性、批量准入、批量稳定性、快速验证 | 数值 | 95 分位响应耗时，越大越慢 |
| **平均耗时（毫秒）** | 稳定性、批量稳定性 | 数值 | 平均响应耗时 |
| **综合分（准入）** | 准入、批量准入 | 数值 | 准入评测给出的综合评分 |
| **准入等级** | 准入、批量准入 | A / B / C / D / E / X / F | 由好到差；选它时下方阈值会变成等级下拉 |
| **质量分（场景）** | 场景测试 | 0～100 | 场景题按评分器/关键词打分后的平均分，同「测试场景维护」页评分器机制里的分数口径 |
| **结论等级** | 准入、稳定性、批量准入、批量稳定性、场景测试 | 通过 / 观察 / 不通过 | 系统综合各指标给出的"是否建议继续用"结论 |
| **快速验证结论** | 仅快速验证 | 正常 / 观察 / 疑似异常 | 快速验证专属的健康判定，跟"结论等级"是两套体系，互不重叠 |

## 比较符 + 阈值

数值型指标（成功率、耗时、综合分、质量分）阈值填数字，配合"低于/不高于/高于/不低于/等于"直接比较大小。

等级型指标（准入等级、结论等级、快速验证结论）阈值改成选等级；比较时按等级的好坏顺序比，比如"结论等级 不低于 观察"表示"观察或不通过"都命中（不通过比观察更差）。

## 冷却时长

同一条规则对同一个目标命中一次、发出邮件后，冷却时长（小时）之内即使再次命中也不会重复发信，避免同一个问题反复报警刷邮箱。最短 0.1 小时（6 分钟），支持小数；范围内每次都是独立计时——过了冷却期再命中，才会发下一封。

范围选"全部"时，冷却是按规则本身计时（不区分是哪个目标命中的）；选"指定渠道+模型"时，冷却只针对那一个目标。

## 稳定性抖动（复合规则）

### 为什么需要它

稳定性测试最该报警的情形，恰恰是普通「成功率」阈值抓不到的：**重试会把失败洗掉**。实测 44 次稳定性运行里，`成功率` 有 42 次都是 100%，只有 2 次掉到 78% / 89% —— 配一条「成功率低于 90%」的规则，几乎永远不响。

但同一批数据的**耗时离散度**问题很明显：按运行算 P95÷P50 倍数，正常区间是 2.31～3.59×，而最差那次是 **11.74×**（P50 9.8 秒，P95 115.5 秒）。也就是说，同一次运行里大部分请求 10 秒返回、个别请求要等近 2 分钟。这才是"抖动"。

所以这条规则换了三个能看见抖动的量，任一越界即判不合格。

### 三个子阈值

三项**各自可选，留空 = 不检查该项**，但至少要配一项（一项都不配的规则永远不可能命中，保存时会被拦下）。

| 子阈值 | 越界条件 | 是什么 |
|---|---|---|
| **耗时抖动倍数上限** | P95÷P50 **高于**此值 | 尾部延迟离散度。倍数越大说明"大部分很快、个别极慢"越严重。默认 6：实测 45 次运行里命中 3 次（6.7%），命中的是 6.05× / 7.03× / 11.74×，未命中的分布在 2.31×～4.98× —— 阈值刚好落在两档之间的空隙里 |
| **首次成功率下限** | 首次成功率**低于**此值 | 不含重试兜底的成功率。这一项才看得见被重试掩盖的真实失败。填 0～1 的小数（0.9 = 90%），默认 0.9 |
| **重试额外等待 P95 上限** | 高于此值（毫秒） | 端到端 P95 减去单次 P95，即重试与退避让用户多等的时间。默认留空 |

### 判定与边界

- **只在稳定性测试 / 批量稳定性测试跑完时评估**。其它测试类型（准入、场景、快速验证）跑完这条规则静默跳过——P50 和重试等待本来就只有稳定性汇总里才有，而首次成功率准入虽然也有，但让一条叫"稳定性抖动"的规则在准入运行上触发会很难解释，所以按测试类型明确门禁。
- **算不出的项自动跳过，不误报**。比如历史数据没有重试耗时字段、或 P50 为 0 算不出倍数，这些项直接不检查，不会因为"取不到值"就报警。
- **越界是"高于"/"低于"，不含等于**。倍数恰好等于阈值不算越界。
- **多项同时越界只发一封邮件**，正文逐条列出是哪几项超标、实测值多少、阈值多少。没配置的项不会出现在邮件里。
- **冷却按整条规则共享**。不是每个子阈值各算一个冷却——冷却期内换成另一项越界，也不会再发。

邮件正文形如：

```
规则「稳定性抖动」判定不合格：claude-sonnet-5
  · 耗时抖动 11.74×（P95 115552ms ÷ P50 9844ms），阈值 6×
  · 首次成功率 78%（不含重试兜底），阈值 90%
```

## 稳定性退化（与自身历史比）

### 为什么需要它

固定阈值有个天生做不到的事：**判断"这个模型比它自己以前差了"**。一个平时 P95 30 秒的渠道劣化到 90 秒，和一个平时就 90 秒的渠道，在"P95 高于 60 秒"这条规则眼里长得一模一样——前者是事故，后者是常态。

这条规则改成拿**这个模型最近几次的中位数**，比**它自己先前一段时间的中位数**。阈值不再是绝对值，而是"相对自己退化了多少"。

### 窗口口径

```
时间轴 →
○○○○○○○○○○○○○○○○○○○○  ●●●
└──── 基线 20 次 ────┘  └最近 3┘
   中位数 100% / 32s      中位数 78% / 95s
                          ↑ 跌 22pp、×2.97 → 报警
```

- **最近窗口**（默认 3 次）：含刚跑完这一次。取 3 次的**中位数**是关键——单次偶然的尖峰会被中位数吸掉，只有连着几次都差，中位数才会真的下移。
- **基线窗口**（默认 20 次）：**紧邻最近窗口之前**的那一段，不含最近窗口自身（否则退化会污染自己的基线）。

按 2 小时一测的节奏，默认口径约等于"最近 6 小时 vs 之前 1.7 天"。两个窗口大小都可改（最近 1～20，基线 2～200）。

### 两个判定阈值

各自可选（**留空 = 不查该维**），但至少要配一项。

| 阈值 | 越界条件 | 默认 |
|---|---|---|
| **成功率跌幅** | 基线中位数 − 最近中位数 **达到**此值 | 0.1（= 跌 10 个百分点） |
| **P95 恶化倍数** | 最近中位数 ÷ 基线中位数 **达到**此值 | 1.5（= 慢了一半） |

只抓**退化**，不抓"变化"：P95 变快、成功率上升，一律不命中。

### 判定与边界

- **只在稳定性测试 / 批量稳定性测试跑完时评估**，与「稳定性抖动」边界一致。
- **历史样本不足时静默不判**。基线实际可用样本少于 5 次就不判定——3 个样本的中位数抗不住离群值，冷启动阶段会乱报。新渠道刚接进来的头几次测试因此不会触发。
- **只跟同类历史比**。批量稳定性的聚合行、场景测试、准入评测的历史行都不会混进基线（场景测试的 P95 天然比稳定性高一个量级，混着比会得出荒谬结论）。
- **某一维历史里全是缺测就跳过该维**，不会把"没记录"当成 0。
- **多维同时越界只发一封邮件**，正文逐条列出。
- **冷却默认 24 小时**（其它两种规则默认 1 小时）。因为持续退化会让之后**每一次**运行都继续命中——两个窗口整体下移，2 小时一测的话 1 小时冷却等于每次都发。24 小时把"一次退化事件"收敛成一封信。

邮件正文形如：

```
规则「稳定性退化」判定不合格：claude-sonnet-5
  · 成功率中位数从 100%（前 20 次）跌到 78%（最近 3 次），↓22pp，阈值 10pp
  · P95 中位数从 32230ms（前 20 次）升到 95000ms（最近 3 次），×2.95，阈值 1.5×
```

### 默认值的实测依据

拿 44 次真实稳定性运行逐次回放（模拟每次跑完时的判定），默认口径下：

- 前 7 次因样本不足**不判定**（符合预期，冷启动不乱报）；
- 其余 37 次里**命中 2 次（5.4%）**，都是 P95 维——连着几次从 33 秒慢到 50 秒（×1.55 与 ×1.50）；
- 成功率维**一次都没命中**：该数据集只有 2 次跌破 100%（78% 和 89%）且分散在不同时间，中位数始终是 100%——这正是中位数该有的行为，孤立的一次失败不算"退化"；
- 那次 P95 冲到 115552ms 的**单点尖峰没有命中**：最近三次是 `[29071, 35624, 115552]`，中位数 35624ms，相对基线只有约 ×1.1。它由「稳定性抖动」规则负责（11.74× 远超抖动阈值 6×）。

## 发信配置在哪

这个页面只管"什么时候该报警"，不管邮箱、SMTP 这些——那些在「邮件报警配置」页设置。规则命中了但那边没配好收件人/SMTP，会静默跳过，不会报错，但也收不到邮件。
